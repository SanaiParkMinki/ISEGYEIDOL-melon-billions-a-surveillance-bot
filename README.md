# 이세계아이돌 빌리언스 추적

멜론 누적 스트리밍을 매일 한 번 찍어 쌓고, 빌리언스 클럽 관문까지의 거리와 도달 예상 시점을 보여주는 정적 사이트.

```
index.html                    대시보드 (의존성 없음, 순수 HTML/CSS/JS)
data/history.json             누적 스냅샷 — 유일한 데이터 원본
scripts/collect.py            하루 한 줄 추가하는 수집기
.github/workflows/update.yml  매일 04:00 KST 자동 실행
```

## 켜는 순서

1. GitHub에 새 저장소를 만들고 이 폴더를 그대로 올립니다.
2. **Settings → Pages → Source: Deploy from a branch → main / (root)** 로 두면 `https://<계정>.github.io/<저장소>` 에서 열립니다.
3. **Settings → Actions → General → Workflow permissions** 에서 *Read and write permissions* 를 켭니다. 봇이 커밋을 못 하면 십중팔구 이것 때문입니다.
4. Actions 탭 → `스냅샷 수집` → **Run workflow** 로 한 번 수동 실행해 봅니다.

첫 수집이 성공하면 `data/history.json` 의 `sample: true` 가 사라지고 페이지 상단 경고도 없어집니다.

## 수집기 손봐야 하는 부분

멜론은 누적 스트리밍용 공개 API가 없어서 아티스트 페이지의 HTML에서 숫자를 꺼내야 합니다. 페이지 구조는 예고 없이 바뀌므로 `scripts/collect.py` 의 `PATTERNS` 는 **처음 한 번 직접 확인해서 맞춰야 합니다.**

```bash
python3 scripts/collect.py --dry-run
```

이게 실패하면 브라우저로 아티스트 페이지를 열어 개발자도구에서 누적 수치가 담긴 태그를 찾고, 그 모양에 맞는 정규식을 `PATTERNS` 맨 앞에 추가하세요. 그동안은 눈으로 본 값을 직접 넣어도 기록은 계속 쌓입니다.

```bash
python3 scripts/collect.py --value 856820708
```

같은 날짜를 두 번 실행하면 덮어쓰기 때문에 중복 걱정은 없고, 누적치가 전날보다 줄어들면 파싱 사고로 보고 커밋을 막습니다.

## 곡별 데이터

`data/history.json` 의 `songs` 배열은 지금 수동입니다. 곡 단위 누적은 아티스트 누적과 집계 기준이 달라서, 자동화하려면 곡마다 별도 페이지를 긁어야 합니다. 우선 아티스트 누적 하나만 안정적으로 쌓이는 걸 확인한 뒤에 붙이는 편이 낫습니다.

## 로컬에서 보기

`file://` 로 열면 `fetch` 가 막히니 서버로 띄우세요.

```bash
python3 -m http.server 8000
```

## 알아둘 것

- **가이섬은 소스로 쓰지 않았습니다.** robots.txt에서 자동 접근을 전면 차단하고 있어, 개인용 저빈도라도 명시적 거부를 넘는 셈이 됩니다.
- 멜론 이용약관도 자동 수집에 우호적이지 않습니다. 하루 1회·비상업·개인 기록 용도라면 현실적 위험은 법적 책임보다 IP 차단 쪽입니다. 주기를 더 촘촘하게 가져갈 이유는 없습니다 — 누적치는 하루 단위로도 충분히 움직입니다.
- 빌리언스 등급은 **아티스트 누적** 기준입니다. 곡 하나의 성적과 헷갈리지 마세요. 10억 브론즈 / 20억 실버 / 50억 골드 / 100억 다이아.
- 도달 예상일은 최근 7일 속도를 그대로 연장한 값이라, 컴백 직후에는 과하게 낙관적으로 나옵니다.
